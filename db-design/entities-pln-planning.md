# Planning: Entity Catalog (`pln`)

> **New domain — no legacy MyERP+ equivalent.** Planning (`pln`) is a fresh module
> added as part of the enterprise inventory recommendation (resolved
> [README §8](README.md#8-resolved-decisions-2026-05-17) #27, 2026-05-18).
>
> **Scope:** MRP-lite (Material Requirements Planning level I) — reorder policies
> per item/warehouse, demand forecasting, supply/demand explosion run,
> and approved replenishment suggestions that convert to `pur_requisitions` or
> `mfg_work_orders`. Does **not** include capacity planning (RCCP/CRP) or
> time-phased scheduling — those are deferred.
>
> **Position in the module stack:**
> ```
> DEMAND: sls_orders / mfg_work_orders / pln_demand_forecasts
>    ↓ explosion (pln_mrp_runs)
> SUPPLY: inv_stock_balances − inv_stock_reservations + pur_orders (scheduled receipts)
>    ↓ net requirement
> OUTPUT: pln_replenishment_suggestions → pur_requisitions | mfg_work_orders | inv_stock_movements (TRANSFER)
> ```

Field-level model. Types are Prisma/Postgres (PK/FK = **`BigInt`**). All entities carry
global **audit + soft-delete** columns (see [README §3](README.md#3-global-conventions)).

Legend: 🔑 business key · ➜ FK · ◆ enum · ○ nullable. Qty `Decimal(19,4)`;
money `Decimal(19,4)`.

## Reorder policies (`pln_*`)

### ErpPlnReorderPolicy → `pln_reorder_policies`

Per-(item, warehouse) override of the base `md_items` reorder parameters. Allows
warehouse-specific safety stock, lead times, and lot sizing. When absent, the
MRP run falls back to `md_items.minStock`/`maxStock`/`reorderQty`.

| Field | Type | Notes |
| --- | --- | --- |
| id | BigInt PK | |
| itemId ➜ | BigInt → Item | target item |
| warehouseId ○ ➜ | BigInt → Warehouse | null = applies to all warehouses not otherwise specified |
| safetyStock | Decimal(19,4) | minimum buffer to maintain |
| reorderPoint | Decimal(19,4) | trigger level (on-hand + on-order ≤ ROP → suggest replenishment) |
| minOrderQty | Decimal(19,4) | minimum order quantity |
| maxOrderQty ○ | Decimal(19,4) | upper cap (null = unconstrained) |
| reorderQty | Decimal(19,4) | fixed qty when `lotSizeMethod = FIXED_QTY` |
| lotSizeMethod ◆ | `LotSizeMethod` | `LOT_FOR_LOT` (default) / `FIXED_QTY` / `EOQ` / `MIN_MAX` |
| eoqQty ○ | Decimal(19,4) | EOQ result (can be pre-calculated or system-computed) |
| leadTimeDays | Int | procurement/production lead time in calendar days |
| preferredSource ◆ | `ReplenishmentSource` | default `PURCHASE`; `MANUFACTURE` if item produced in-house |
| preferredSupplierId ○ ➜ | BigInt → Partner | default supplier for purchase suggestions |
| isActive | Boolean | |

`@@unique([itemId, warehouseId])`, `@@index([itemId])`.

## Demand forecasts (`pln_*`)

### ErpPlnDemandForecast → `pln_demand_forecasts`

Planned/expected demand per item, warehouse, and fiscal period. Source can be
manual (planner entry), aggregated from `sls` contract bookings, or generated by
the AI engine (`apps/ai-engine`). Consumed by `pln_mrp_runs` as one demand signal
alongside actual open orders.

| Field | Type | Notes |
| --- | --- | --- |
| id | BigInt PK | |
| itemId ➜ | BigInt → Item | |
| warehouseId ➜ | BigInt → Warehouse | demand at warehouse level |
| fiscalPeriodId ➜ | BigInt → ErpFiscalPeriod | planning period |
| forecastQty | Decimal(19,4) | expected demand qty (base unit) |
| confirmedQty ○ | Decimal(19,4) | locked qty (overrides forecast for MRP explosion) |
| source | String | `MANUAL` / `AI_ENGINE` / `SLS_CONTRACT` / `HISTORY` |
| sourceRefId ○ | BigInt | e.g. `sls_orders.id` if derived from sales contract |
| notes ○ | String | |

`@@unique([itemId, warehouseId, fiscalPeriodId])`,
`@@index([fiscalPeriodId])`, `@@index([itemId, warehouseId])`.

## MRP run (`pln_*`)

### ErpPlnMrpRun → `pln_mrp_runs`

A planning explosion run: reads demand (open orders + forecasts), available supply
(on-hand − reserved + scheduled receipts from open `pur_orders`/`mfg_work_orders`),
and reorder policies to compute net requirements and generate
`pln_replenishment_suggestions`. Follows the same **run entity** pattern as
`inv_cost_recalculations`.

| Field | Type | Notes |
| --- | --- | --- |
| id | BigInt PK | |
| docNumber 🔑 | String unique | via `sys_document_numberings` |
| runType | String | `REORDER_POINT` (simple ROP check) / `MRP` (full explosion) |
| planHorizonStart | Date | explosion window start |
| planHorizonEnd | Date | explosion window end |
| itemScopeId ○ ➜ | BigInt → Item | null = all items; single item for spot-run |
| warehouseScopeId ○ ➜ | BigInt → Warehouse | null = all warehouses |
| includeForecast | Boolean | whether `pln_demand_forecasts` feed gross requirements |
| includeOpenOrders | Boolean | whether `sls_orders`/`mfg_work_orders` feed requirements |
| status ◆ | `MrpRunStatus` | `DRAFT`/`PROCESSING`/`COMPLETED`/`FAILED` |
| startedAt ○ | DateTime | |
| completedAt ○ | DateTime | |
| suggestionCount ○ | Int | count of generated suggestions (informational) |
| notes ○ | String | failure reason / planner note |

Relations: `lines ErpPlnMrpRunLine[]`, `suggestions ErpPlnReplenishmentSuggestion[]`.
`@@index([status])`, `@@index([planHorizonStart, planHorizonEnd])`.

### ErpPlnMrpRunLine → `pln_mrp_run_lines`

Classic MRP worksheet: one row per `(item, warehouse, period)` within the run.
Captures the supply/demand snapshot at run time (frozen; re-run to refresh).

| Field | Type | Notes |
| --- | --- | --- |
| id | BigInt PK | |
| mrpRunId ➜ | BigInt → ErpPlnMrpRun | |
| itemId ➜ | BigInt → Item | |
| warehouseId ➜ | BigInt → Warehouse | |
| fiscalPeriodId ➜ | BigInt → ErpFiscalPeriod | planning bucket |
| grossRequirement | Decimal(19,4) | total demand (open orders + confirmed forecast) |
| scheduledReceipt | Decimal(19,4) | supply already in flight (open PO/WO qty) |
| projectedOnHand | Decimal(19,4) | projected balance at start of period |
| safetyStock | Decimal(19,4) | snapshot from `pln_reorder_policies` / `md_items` |
| netRequirement | Decimal(19,4) | max(0, grossRequirement − (projectedOnHand − safetyStock) − scheduledReceipt) |
| plannedOrderQty | Decimal(19,4) | net req adjusted for lot size (0 if none needed) |
| lineNo | Int | row order within run |

`@@index([mrpRunId])`, `@@index([itemId, warehouseId, fiscalPeriodId])`.

## Replenishment suggestions (`pln_*`)

### ErpPlnReplenishmentSuggestion → `pln_replenishment_suggestions`

System-generated action card from a run (or reorder-point trigger). Approved by
planner → **auto-converts** to:
- `pur_requisitions` (source `PURCHASE`)
- `mfg_work_orders` draft (source `MANUFACTURE`)
- `inv_stock_movements` type `TRANSFER` (source `TRANSFER`)

A suggestion is **never directly executed** — it is a proposal that routes to the
appropriate operational module upon approval.

| Field | Type | Notes |
| --- | --- | --- |
| id | BigInt PK | |
| mrpRunId ○ ➜ | BigInt → ErpPlnMrpRun | null if triggered by ad-hoc reorder check |
| itemId ➜ | BigInt → Item | |
| warehouseId ➜ | BigInt → Warehouse | destination warehouse |
| source ◆ | `ReplenishmentSource` | `PURCHASE` / `MANUFACTURE` / `TRANSFER` |
| sourceWarehouseId ○ ➜ | BigInt → Warehouse | for `TRANSFER`: origin warehouse |
| preferredSupplierId ○ ➜ | BigInt → Partner | from policy; for `PURCHASE` |
| requiredQty | Decimal(19,4) | planned order qty (from MRP line) |
| suggestedQty | Decimal(19,4) | lot-size–adjusted qty to order/produce |
| neededByDate | Date | demand due date (action due = neededByDate − leadTimeDays) |
| actionDueDate | Date | latest start date to meet `neededByDate` |
| status ◆ | `SuggestionStatus` | `PENDING`/`APPROVED`/`REJECTED`/`CONVERTED` |
| convertedToDocType ○ | String | `PUR_REQUISITION` / `MFG_WORK_ORDER` / `INV_TRANSFER` |
| convertedToDocId ○ | BigInt | FK to the created operational doc |
| rejectionReason ○ | String | planner's note on rejection |
| approvedById ○ ➜ | BigInt → ErpUser | |
| approvedAt ○ | DateTime | |

`@@index([status])`, `@@index([itemId, warehouseId, status])`,
`@@index([actionDueDate])`, `@@index([mrpRunId])`,
`@@index([convertedToDocType, convertedToDocId])`.

## Derived (not written tables)

### pln_atp_view *(view — available-to-promise)*

```
ATP(item, warehouse) =
  inv_stock_balances.qty
  − Σ inv_stock_reservations WHERE status = ACTIVE
  + Σ pur_order_lines (open, not yet received)  ← scheduled receipts
```

Consumed by `sls` quote/order to commit delivery dates, and by `pln_mrp_runs`
for `scheduledReceipt` population. Not written directly.

## Integration map

| Module | Direction | Event | What `pln` does |
| --- | --- | --- | --- |
| `md_items` | reads | `minStock`/`maxStock`/`reorderQty` | fallback reorder params when `pln_reorder_policies` absent |
| `inv_stock_balances` | reads | on-hand qty + cost | `projectedOnHand` input to MRP line |
| `inv_stock_reservations` | reads | ACTIVE reserved qty | deducted from ATP view |
| `pur_orders` | reads | open, undelivered lines | `scheduledReceipt` input |
| `mfg_work_orders` | reads | planned outputs (produced items) | `scheduledReceipt` for manufactured items |
| `sls_orders` | reads | open, unshipped lines | gross requirement input to MRP |
| `pln_demand_forecasts` | reads | confirmed qty | gross requirement input (when `includeForecast = true`) |
| `pur_requisitions` | **writes** | suggestion `CONVERTED` (PURCHASE) | creates requisition via `pur` module |
| `mfg_work_orders` | **writes** | suggestion `CONVERTED` (MANUFACTURE) | creates WO draft via `mfg` module |
| `inv_stock_movements` | **writes** | suggestion `CONVERTED` (TRANSFER) | creates transfer movement via `inv` |
| `sys_fiscal_periods` | reads | period bucket | aligns MRP horizon to fiscal calendar |
| `sys_audit_logs` | **writes** | approve/reject/convert events | traceability |

> **`pln` never touches `fin_ledger_entries` directly.** GL postings happen
> when the *converted operational docs* are posted in `pur`/`mfg`/`inv`.
